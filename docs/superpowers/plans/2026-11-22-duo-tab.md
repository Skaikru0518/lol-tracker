# Duo Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Duo profile tab listing repeat teammates and comparing the profile with one of them, plus the Overview "Recently played with" panel moved onto the same data.

**Architecture:** Pure aggregation in `src/lib/duo/` (unit tested) over a narrow SQL projection of the profile's last 50 stored Rift games; two DB-only API routes; TanStack Query hooks; small client components under `src/components/summoner/duo/`.

**Tech Stack:** Next 16 App Router, TypeScript, Prisma `$queryRaw` on Postgres JSONB, Zod, TanStack Query, Vitest, Tailwind.

**Spec:** `docs/superpowers/specs/2026-11-22-duo-tab-design.md`

## Global Constraints

- No Riot API calls anywhere in this feature; Postgres only (`scoreAndCache` for missing ranked scores is allowed).
- Window: the profile's last 50 stored games with `queueId` in `RIFT_QUEUE_IDS` and `gameDuration >= REMAKE_SECONDS` (not `isRemake`), newest first.
- Duo partner: same `teamId` as the profile in ≥ 3 games of the window; sort by games desc, then win rate desc; at most 10.
- Win-rate difference from unrounded rates, rounded once; `null` when the profile has no games in the window without that partner.
- Crown only on a strictly higher score, only when both scores exist.
- pnpm only; no migrations; very few comments (only the non-obvious why); Zod schemas with inferred types in `src/lib/validators/`; rem sizing; works at 375px.
- Both API routes: 400 on missing params, `rateLimited(req, "<scope>")` → 429, `console.error` + 500 on failure, wrapped in `withApiLog`.
- The working tree has unrelated uncommitted changes: each commit stages only the files its task names.

## Review Focus

- A partner whose stored participant has empty `riotIdGameName` (old documents) shows as "Unknown", never a blank row → Task 1 test `names a partner without a Riot ID Unknown`.
- A profile that played every window game with the partner gets no difference instead of a NaN or 0 → Task 1 test `gives no difference when every game had the partner`.
- Equal scores in a shared game crown nobody and count for no one → Task 3 test `crowns nobody on equal scores`.
- Unscored (normal queue) shared games show both K/D/A but no scores and are left out of the carried counts → Task 3 test `leaves unscored games out of the carried counts`.
- `with` equal to the profile's own puuid is rejected with 400 instead of comparing a player with themselves → Task 3 route check, verified in Step 6.
